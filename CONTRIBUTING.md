# Contributing to dsh-pstack

dsh-pstack is the pstack workflow port for DeepSeek Harness. Changes here usually take one of three shapes: documentation, plugin code under `src/`, and verification work under `playground/`. This file covers what a change has to satisfy before a maintainer merges it.

## Before you start

- Read `AGENTS.md` at the repository root, then the `AGENTS.md` in the directory you are changing. Each directory document carries the rules for that directory.
- Decisions under `docs/decisions/` bind the implementation. `docs/decisions/AGENTS.md` explains how to find the records that match your paths, and an accepted record outranks a preference.
- Put throwaway files in `.tmp/`. Do not commit them.

## Setup

Node 24.21.1 or newer, and pnpm 12.15.0.

```sh
pnpm install
```

`prepare` also runs `vp config` and syncs the vendored skills, so the first install needs network access.

## Check your change

```sh
pnpm run ci
```

This runs `vp check`, the type check, the test suites, the native, surface, and compatibility checks, and a build. It is the same command the release workflow runs, so a green local run means the pull request check runs the same steps.

## Pull requests

- Keep one concern per pull request. A documentation fix and a behavior change are two pull requests.
- Commit messages follow Conventional Commits. A breaking change uses the `type!:` form, for example `feat!: ...`.
- Documentation is localized. A change to `README.md` usually needs the same change in `README.zh.md`, and `src/dsh.md` pairs with `src/dsh.zh.md`.
- Do not edit `changes/`. The release note is generated by the maintainer from the commits between two tags.
- Do not bump the version or create a tag. Releases are maintainer-only.
- Describe how you verified the change. A test run, a reproduced failure, or a screenshot of the real UI all count. "Works locally" does not.

## Review

Every pull request needs the `ci` check to pass and one maintainer approval before merge. Expect a question about the alternative you rejected when a change picks one design over another; that is what the records under `docs/decisions/` are for.

## Licensing

There is no CLA. Contributions are accepted under the MIT license in `LICENSE`. Bundled upstream material and vendored skills keep their own licenses, so check the source project before copying text or code from one.
