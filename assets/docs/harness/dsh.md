# DSH harness mapping

> This package ships its static assets, one bundled skill provider, the `pstack_subagent` delegation tool, the ported workflow skills and playbooks, restricted read-only history through `pstack_history`, `pstack_script` for running the bundled CLIs on the Host's own runtime, the official worktree integration mounted on demand, and a long-running-workflow pass that maps automatic goals, reminder heartbeats, and local watchers onto the host tools that actually exist.
> The tables below are the target contract, not proof that a capability is installed in a profile.

Generated from `scripts/capabilities.ts` into `assets/docs/harness/dsh.md`. Edit the table, not this file.

## Coverage

- `mapped`: DSH has a direct equivalent, and the port keeps the upstream intent.
- `degraded`: DSH has a partial equivalent, and the row states what is lost.
- `preserved`: the upstream behavior stays as written, inside its narrower scope.
- `excluded`: the feature is not carried, and every skill that needs it is adapted.
- `deferred`: a later unit delivers it, and `Unit` names that unit.

A row without `mapped` carries a reason and a delivery unit. A numeric unit names when the
capability lands; `not planned` marks a gap this port does not close. Neither is evidence
about this tree.

## Paths, models, and host features

| Upstream | DSH | Coverage | Unit | Note |
| --- | --- | --- | --- | --- |
| model slug, reasoning effort, `fast` | `role` resolved from `$DSH_HOME/pstack-models.md`, plus `reasoningEffort` per delegation | mapped | - | A role value is `inherit-parent`, `auto`, `<provider>/<model>`, or `<provider>/<model> [effort]`. The value splits at its first `/`, so a model id may keep its own vendor prefix (`gateway/vendor-a/model-x`); no segment may be empty. The role's effort is the level that role starts at, not a ceiling or a floor: `pstack_subagent` takes `reasoningEffort` to raise or lower it for one delegation, and a child can change its own with `set_reasoning_effort`, which applies from its next step. Both are validated against the live adapter metadata, per panel entry, before a child starts, and a refusal lists that model's real efforts. No model id is hardcoded in the assets, and no effort token is either: the adapter's own list, ordered from least to greatest, supplies both the vocabulary and what one step is. |
| `~/.cursor/rules/pstack-models.mdc` | `$DSH_HOME/pstack-models.md`, read for each new delegation | mapped | - | `/setup-pstack` writes the file and `pstack_subagent` re-reads it on every delegation. An unreadable file is an error, not an empty configuration. |
| `.cursor/skills`, `~/.cursor/skills` | `assets/skills/<name>/SKILL.md` inside this package | mapped | - | Skills ship inside the package and are read in place; nothing is copied into `$DSH_HOME/skills`, and no directory is watched. |
| `~/.cursor/plugins`, `.cursor-plugin` | absolute resource paths inside this package | mapped | - | Each candidate carries its own skill directory as the resource base, so `references/` and `scripts/` resolve next to `SKILL.md`. |
| `~/.cursor/projects/.../agent-transcripts` | `pstack_history`, a restricted read of raw `sessionQuery` events | degraded | 5 | The tool pages one fixed observation of the calling session or a reviewable direct child, inside the caller's workspace; there is no transcript directory to read, no arbitrary session id, and no descendant traversal. A cold read from persistence cannot separate the stored log from the read-time interrupted-turn closers rc.3 appends, so per-event provenance is reported undeterminable and a full transcript audit stays unfinished for those sessions. The live/prepared split, pagination, and lease release are unit-tested; no real profile read has run yet. |
| search across other sessions in the workspace, which `recall` and `automate-me` both do | `session_search` and its four sibling tools, mounted only by the official session-search bundle | degraded | 5 | Cross-session search lives in the optional `@deepseek-ai/dsh-experimental-session-search` bundle, which the official bundles ship switched off, so a profile has it only when the operator enables it in Plugins. `pstack_history` does not substitute for it: that tool reads the calling session and its reviewable direct children, and refuses any other id. Without the bundle, `recall` and `automate-me` still work inside the current session and its direct children and must report the cross-session half as unavailable instead of presenting it as done. The bundle mounts its own isolated `sessionQuery` provider with a lazy in-memory index, so enabling it does not change what `pstack_history` reads. This package does not mount it on the operator's behalf: it adds five global tools to every Agent, invalidates each live Session's cached request prefix once, and keeps an in-memory index after the first search. |
| agent store | `.audit/` under the repository, stated in a prompt context; the operator may name another directory | degraded | 4 | Upstream's store is a per-agent directory the host states in the system prompt, outside the repository and outliving the session. This host has no store, but it does have dynamic prompt context (`SystemPrompt.context`, a durable user-role snapshot), so `pstack` registers one required contribution naming `.audit/` as the place for plans, trails, and orchestration state. That restores the part that was missing: a child knows the path without being told, which is what makes a resume cheap. What is still lost is durability across sessions — nothing resumes from `.audit/` on its own, and a resumed child is handed its standing orders again rather than told to re-read them. The operator's named directory still wins, so the placement is a default rather than an assignment. |
| `paths:` auto-attach globs in SKILL.md | not consumed; skills load by explicit invocation | degraded | not planned | Automatic attachment by file glob has no equivalent, so `typescript-best-practices` is explicit-invocation only and its body says so. The frontmatter field is dropped from the generated skill rather than shipped as a no-op. |
| Custom Mode | an explicit `/poteto-mode` on each new task | degraded | 4 | No persistent mode or keyboard shortcut exists. The ported skills say so at the step where a mode would have applied. |
| `/loop` | `create_goal` for automatic continuation, plus `schedule_create` only as a timed heartbeat | degraded | 6 | There is no command to type and no event subscription.
