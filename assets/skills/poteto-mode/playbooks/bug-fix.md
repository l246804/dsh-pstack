### Bug fix

**You own this task. Plan, review, verify.** Delegate investigation and the fix to `pstack_subagent` children, stay in the lead. Read the Subagents section of the `poteto-mode` skill at its absolute resource path before the first spawn. Start from the level the role line names, raise it for hard work and lower it for routine work by passing `reasoningEffort`; a child that cannot call `set_reasoning_effort` keeps the level you gave it.

Be scientific. Every shipped line traces to runtime evidence. Belt-and-suspenders that "might help" is a hypothesis, not a fix. It does not ship. When evidence refutes a hypothesis, revert what it motivated. The smallest change the evidence justifies ships, nothing more.

1. Reproduce it yourself on the matching surface, through the control path the `poteto-mode` Non-negotiables section names, even when a debug or instrumentation protocol says to ask the user to reproduce. That path is a real project driver or verification skill; when the project has none, report the surface as unreachable instead of treating a unit test as reproduction. Ask the user only with a stated, specific reason the control surface cannot reach the target, and only after driving it as far as it goes. If it won't reproduce directly, synthesize the trigger, tighten conditions, or instrument until it fires.
2. Binary-search the cause. Form the candidate hypotheses, then rule them out until one survives. Seed them by reading the `how` skill over the affected subsystem and the `why` skill for regression history, each at its absolute resource path. Each pass, take the split that cuts the most remaining problem space, get runtime evidence, eliminate. When program state is unclear, add instrumentation or logging and read it as the code runs. Don't guess. Keep a long or stubborn hunt in this Session: keep the hypothesis list current and re-read your own instrumentation output. Automatic continuation requires the goal round driver and the Autonomous run playbook's exit predicate; neither replaces this runtime evidence loop. Confirm the surviving *mechanism* with runtime evidence before the step-3 architect/interrogate fan-out.
3. Plan the fix. If it crosses a function boundary, read the `architect` skill's `SKILL.md` at its absolute resource path and run it first. Delegate implementation to a `pstack_subagent` child with `agent: "poteto-agent"` and `role: "bug-fix"`, naming a specific scope; a role the file does not name inherits the parent route, and a route that does not resolve fails the call with the role file named.
4. Verify on the same surface. The original repro now passes. "Inconclusive" or wrong-surface is not a pass. Flag it. Unit tests show branch behavior, not bug absence.
5. Stage the commits so the failing repro lands before the fix in git history. Read the `tdd` skill's `SKILL.md` at its absolute resource path for the failing-test-first cadence when the bug has a cheap local test path. Skip it when the test would be expensive, integration-heavy, or unclear.
   This is the canonical `principle-sequence-verifiable-units` move, the failing test first and the fix on top; read that skill's `SKILL.md` at its absolute resource path.
6. Read `playbooks/opening-a-pr.md` next to this file and run it.
