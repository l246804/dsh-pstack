### Autonomous run

**You own the exit condition. Define done, then drive to it without stopping.**

1. State the exit condition as a checkable predicate before the first iteration (tests green, repro fixed, all N PRs merged, pixel-diff zero). A predicate a stranger cannot run is not a predicate, and a duration is not one either.
2. Register that predicate as the goal before the first iteration. This host has no loop command to type, so `create_goal` is what carries a run: the goal is durable in this Session, it holds the round cap, and automatic continuation rounds proceed from it. Continuation needs the goal round driver mounted in the profile, so read `get_goal`, check whether continuation is armed and whether rounds are actually starting, and report which of the two you have instead of implying a loop. `create_goal`, `edit`, `pause`, and `resume` each need a direct request from the operator in this top-level turn, so a child cannot register or steer a run on your behalf.

   Pick the wake mechanism by what this host actually has. A timed input is `schedule_create`, which delivers a reminder into this Session at a wall-clock time: use it as a heartbeat sized to when re-checking is worth a turn, never as an event subscription, because a reminder cannot watch anything, and a child cannot arm one at all. A real event needs a real watcher: a script that blocks until the condition changes and then exits, started as a background job so its settlement arrives as a notice, or a poll loop you run and read. If neither fits the event you care about, say the run is supervised and check it yourself. Start from the level the role line names, raise it for hard work and lower it for routine work by passing `reasoningEffort`; a child that cannot call `set_reasoning_effort` keeps the level you gave it.
3. Each iteration makes the smallest change the evidence justifies, verifies it against the predicate, commits if it advanced, discards changes that didn't help. Belt-and-suspenders that "might help" gets reverted, not left to ride.
   Sequence the work via the **sequence-verifiable-units** principle skill, verifying each unit before the next instead of batching checks at the end.
4. Mid-run discoveries are yours. Address broken skills, related bugs, flaky verifiers, review noise, tooling failures, orphaned follow-ups, and fixable drift yourself via poteto-mode. Put out-of-band fixes in their own PR. Do not park reversible work for the operator or ask a question instead of acting. Surface only irreversible actions, genuine product or preference calls no experiment can settle, or a real dead end. Keep the predicate as the main drive, and return to it after each side fix.
5. Checkpoint every iteration via the **show-me-your-work** skill, a row for what changed and whether the predicate moved.
6. Stop when the predicate is met, and record it with `update_goal` action `complete`, which also disarms continuation. Report a block only when the same concrete condition survived the deployment's consecutive-round threshold, three by default, and state it in `blocked_reason`; the host rejects a block before that count, and a plateau is not a block, so keep going and pivot your approach to push past it. Surface a genuine dead end rather than spinning, and never relax the predicate to declare victory. Pause and resume belong to the operator's direct request, and a host restart leaves an active goal disarmed, so a resumed Session has to be rearmed on purpose. A repeated-prompt driver such as Ralph is used only when the operator names it, and it never replaces the predicate.

**Reply:** the exit condition, iterations run, what landed, what was discarded, final predicate state.
