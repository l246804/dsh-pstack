# DSH 适配文档编写规则

适用于 `native/dsh.md`、`native/dsh.zh.md`、`src/dsh.md` 和 `src/dsh.zh.md`。本文件定义文档结构、块职责和写作约束。

## 结构

核心块按以下顺序出现：

```text
Tools
Subagent fields
Models
setup-pstack
Paths
Cursor-only features
```

`src/dsh.md` 可以增加与插件能力相关的扩展块。扩展块不是白名单，也没有固定数量。按依赖关系放置：

- 定义工具或能力：放在 `Tools` 之前。
- 扩展子代理或团队协作：放在 `Subagent fields` 之后。
- 本地替代或跳过策略：放在 `Cursor-only features` 之前。

新增块必须有独立职责；不要复制其他块已有的内容。当前 `src/dsh.md` 使用 `Plugin tools`、`Agent Teams`、`Local replacements`，这些只是当前交付内容，不是新增块的限制。

这些块是正式内容，不是脚注。没有对应内容时省略该块，不要写空占位。新增、删除或移动块后同步更新本规则和对应的 `dsh.zh.md`。

## 通用写作约束

以下约束适用于所有块。

- 目标文档是运行时映射表。每行只回答“这一项在 DeepSeek Harness 里映射成什么，缺失或不可用时怎么办”，不回答“它内部怎么做”。
- 不复述运行时契约：不写参数必填或可选清单、枚举、返回结构、错误分支、schema 版本号、字段字面量、默认家目录或环境变量默认值。需要时指向对应工具或配置位置。`setup-pstack` 的写入步骤是例外，因为它要生成用户配置文件而不是描述工具契约。
- 不写入当前环境的实例值，例如具体模型、provider、模型路由、主机名、账号、私有仓库或本地路径。用占位符或通用记法表达规则。
- 不引入只有本仓库内部才懂的简称或基线名。需要指代运行时能力时，用读者在会话里能看到的名称，或直接省略。
- 一个事实只写一次。重复时保留最靠近使用动作的一处，其余删除或指向该处。
- 描述插件工具时，作用范围只限该插件实际提供的资源。不要用另一个工具的行为定义本工具的能力。
- 每格默认不超过三句。写不下通常说明这一格在抄实现细节，应删减或移到证据。
- 表格按“Cursor 项 → DSH 差异”组织，不列官方能力清单，不写具体包名、开关名和安装步骤。

## 分块规则

### 开头说明

- 说明本文件是运行时映射表，不是 schema 手册或插件目录。
- 只写通用可用性规则：使用当前 session 实际可见的工具；缺失时按对应行 fallback；不假设可选插件已启用。
- 不列官方插件能力清单，不写具体插件包名、开关名称或安装步骤。

### Plugin tools（仅 src）

- 每个插件工具一行，写名称、用途和调用边界。
- 工具用途集中在这里；其他块只引用工具名，不重复用途说明。

### Tools

- 每个 Cursor 工具或操作一个单元格。
- 先写 DSH 替代名称，再写字段、工具或能力不存在时的动作。
- 替代工具是本插件提供时，只写替代关系和调用者必须知道的一条约束；完整用途指向 `Plugin tools`。

### Subagent fields

- 覆盖当前上游 harness 文档中的字段；上游增删字段时同步本块，不预设固定行数。
- 写清字段不存在时是省略、由 prompt 承载、由 agent 文件承载，还是用另一个字段替代。
- 每行只写该字段的映射和缺失时的处理，不重复 Tools 或 Plugin tools 的工具说明。

### Agent Teams（仅 src）

- 说明会话启用 Agent Teams 时的协作边界：`pstack_subagent` 何时创建团队任务、如何绑定 owner、如何完成或移交。
- 不复述团队工具的 schema、参数或返回结构；`pstack_roles` 报告的是模型路由而非团队成员。

### Models

- 写清 provider、model、reasoning effort 的映射，以及发现能力不可用时的默认或继承规则。
- 角色文件行写清文件位置、谁在什么时机读取、缺失时的默认行为。具体字段和默认值指向配置或类型来源。
- 不写具体模型清单；模型列表由当前运行时提供。

### setup-pstack

- 说明 DSH 的配置文件位置、持久化和覆盖规则，以及检测失败或模型不可用时的 fallback。
- 不复制上游完整步骤，只写与 DSH 不同的部分。
- 写入步骤只写行为，以及目标文件的最小持久化结构：路径、`version`、`roles` 和 route-object 形状。写清覆盖整文件保证幂等、缺失角色继承父路由、检测失败请用户补充。不写读取器的错误分支或工具参数。

### Paths

- 一个路径差异一个单元格，写清 DSH 路径、读取限制和生成物边界。
- 不写安装路径或包布局细节，不写环境变量默认值。

### Local replacements（仅 src）

- 只登记确实需要本地替代实现的依赖技能或外部技能，一行一个，写替代技能或 fallback。
- 已在能力分析里判定为“无需处理”或“显式跳过”的项不要登记在这里。确需跳过或报告的能力放 `Cursor-only features`。
- 不写包名、安装方法，也不写渲染或运行时实现细节。

### Cursor-only features

- 每个 Cursor 专属能力一行，写清实际处理：跳过、替代、阻止或报告。
- 使用明确的默认动作，不写“应该”“可以尝试”。
- 这里的“替代”只指行为层的处理说明；需要专门技能或工具的本地替代方案写在 `Local replacements`。

## 证据和检查

- native 的逐行证据放在 `native/dsh-evidence.md`；每条核心表格行必须有对应证据。
- 修改 `dsh.md` 后同步对应的 `dsh.zh.md`，保持 section 数、行数、Cursor 单元格和代码标识符一致。
- 生成前对照本文件自检：没有抄运行时 schema 字面量，没有跨块重复，没有未定义的内部简称，`Local replacements` 只含真实替代项。
- `native/scripts/generate-pstack.ts` 负责生成树；修改后人工检查结构并运行 `vp run native:generate:check`。
