# 升级 DSH 基线

运行时换成新的 DSH 版本后，本仓的声明、装配、适配答案、证据和缺口要一起跟上。本文只写顺序和判断点，不写具体版本号、字段值或工具名。那些以 `package.json`、`pnpm-workspace.yaml`、根 `cordis.patch.yml` 和各文档的实际内容为准。

## 触发

`dsh --version` 与 `package.json` 的 `engines.dsh` 不一致时。

## 先评估影响面

不是每次升级都要走完整流程。新版可能只动了与本仓无关的东西，这时重写适配答案和证据只会制造无意义的 diff，还会让「改过」看起来像「变过」。

先做完整顺序的第 1 步，再按下面两样判断。机器判定要在新版本上跑，所以它排在改完声明之后。

1. **机器判定。** `vp run ci`。类型对着新版本编译，契约测试读已安装的包，形状有没有动它先说。
2. **人的判定。** 读升级指南登记的破坏面，逐条判断落在哪一层。

结论只有两条路。

- **完整路径。** 任一破坏面落在本仓的声明面上，即 `src/`、根 `cordis.patch.yml`、适配答案覆盖的事实、包装工具的原生契约。从完整顺序的第 2 步接着走。
- **轻路径。** 没有破坏面落在这些面上。只做四件事：改版本声明；跑两个机器检查；证据里若有版本标签，只改标签不复核内容；在新版本上重跑 playground，用新的快照代表这个版本验证过。

轻路径不是免验证。它免的是重写依据，不免验证本身。快照里记录的运行身份就是「这个版本验证过」的证据，不需要另外在文档里写一句声称。

判不出影响面时按完整路径走。结论要留痕：完整路径在 PR 里逐项写，轻路径写进本次 playground 的 findings，写明看过哪些破坏面、为什么判定对本仓无影响。

## 完整顺序

1. **改版本声明。** `engines.dsh`、`pnpm-workspace.yaml` 里 DSH 相关 catalog、lockfile、两份 README 的要求行与徽标。兼容表不在这里改，它只记已发布事实，新范围由发版脚本在发版时写入。

2. **审装配。** 根 `cordis.patch.yml` 是本仓的装配清单，DSH 的工具、preset 和插件接口一变，模型看到的工具面就跟着变，所以这一项必须逐行核，不能只看报错。
   - 每个被引用的插件与行 id 是否仍然存在。
   - 每行的 `config` 字段是否仍是该包 `Config` 声明的字段，语义是否未变。
   - preset 组合是否仍成立，子代理 preset 需要的服务是否仍由当前组合提供。
   - 工具名、技能目录、`dsh.client.inject` 是否仍是当前名称。
   - 新增或退役的官方工具是否需要本仓声明或屏蔽。

3. **刷适配答案。** 逐个替换项对运行时求证，改 `native/` 与 `src/` 的答案，以及每个本地化版本。

4. **刷证据。** 每个替换项的可复查位置重新落一遍。位置会失效，用符号名而不是行号。

5. **复核缺口。** 新机制可能让某条缺口不再成立。改判是用户的决定，不自行改状态；判据见 `native/AGENTS.md`。

6. **重建生成树。** `vp run native:generate`，产物与 `native/dsh.md` 同波提交。

7. **核对工具契约。** 按 `src/docs/dsh-tool-adapters.md` 跑契约测试并复核差异清单。

8. **验证。** `vp run ci` 与 `vp run native:generate:check` 全绿。

9. **发版。** 兼容表新分组由发版流程写入，迁移说明由发版说明承载。

## 判断点

- 一条改动记录的是事实还是答案，决定它归第 1 步还是第 3 步。能用命令查出来的是事实，要读运行时才能确认的是答案。
- 破坏面只影响可选插件时，仍要在装配审查里写结论，说明当前组合为何不受影响。
- 无法核实时写未核实，不用旧结论填空。
- 轻路径依赖一轮 playground 快照。跑不了 playground 时轻路径不成立，改走完整路径，或明确记录该版本只有静态验证。
- 版本声明与适配答案可以分成两个提交，各自能单独验证。装配审查的结论跟版本声明一起交。

## 完成标准

完整路径：`vp run ci` 绿，`engines.dsh` 与 `dsh --version` 一致，装配审查每一项都有结论，`vp run native:generate:check` 绿。

轻路径：`vp run ci` 绿，`engines.dsh` 与 `dsh --version` 一致，新版本上的 playground 快照完整，findings 里有判定无影响的结论。
