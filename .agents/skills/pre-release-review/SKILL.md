# 发版前审查

用于本仓发版前的综合审查。单个缺陷或普通文案修改按其原任务范围处理。

## 确定范围

读取根及目标目录的 `AGENTS.md`、架构、术语表和决策检索规则，按 Scope 读取相关记录。记录基准分支、HEAD、工作区状态与审查范围；用户要求隔离时创建 worktree。安装和验证命令从项目配置读取。

默认覆盖本仓维护的文档、运行时代码、构建发布、验证工具和相应测试。生成树、上游副本、技能安装副本、锁文件和历史证据用于核对来源与一致性；修复落在维护源，再按项目流程同步。每个模块记录已审、发现问题或未核实及原因，不能把搜索无命中当作审查通过。

按根 [AGENTS.md 的实现与文档规则](../../../AGENTS.md#实现与文档)，先核对场景依据与文档时效。为新增说明或代码分支找到当前调用方、可达触发条件或已确认需求；只有假设的风险不进入修复清单。

## 文档与决策

文档使用 [writing-for-agents](../writing-for-agents/SKILL.md) 的规则，逐项核对：

- **事实**：对照调用链、类型、配置、测试和实际产物，找漂移、矛盾、缺失前提、无效链接和没有证据的承诺；同时检查本地化版本。非决策文档直接替换或删除失效说明；迁移与兼容能力只描述当前行为和必要操作。
- **归属**：目录文档主要描述本目录职责。跨目录内容保留带触发条件的指针，操作规则回到所属目录，跨模块关系留在项目架构。
- **唯一来源**：合并同义说明，保留独有约束和必要的使用摘要。字段、默认值、文件穷举和脚本列表优先指向源码或配置；稳定契约和不能从代码推导的理由保留在文档。
- **可执行性**：入口指针能触发正确分支，步骤有可核对的完成条件；消除无效指令、重复护栏和多余层级。文档与实现矛盾时先确认哪一方表达有效要求，再决定修复对象。

本综合审查包含决策记录审查。读取 [decision-audit](../decision-audit/SKILL.md)，全仓审查按其 full 模式规则执行；保留 Scope matcher、状态、实现锚点、替代关系和复核日期的命令证据。该技能只报告记录元数据，本次代码审查另行核对实现是否遵守 accepted 决策。记录修改进入 [decision-write](../decision-write/SKILL.md)；历史实现描述按其历史语境判断，不能仅因旧路径或日期而改写。

## 代码与发布

沿当前入口、数据读写和可达的错误路径追踪，结合已有测试核对：

- **行为**：功能或配置是否冲突；失败、取消、重试、并发更新、资源释放和持久化是否保持契约。缺失、损坏、不可用必须按各自语义处理，检查静默吞错、伪成功及未经要求的兜底。
- **结构**：职责和依赖方向是否清晰，是否重复维护状态、重复解析或校验；抽象、文件拆分与通用化是否有真实调用方。精简应减少维护面，不以行数或文件数为目标。
- **类型**：官方契约是否直接复用；本地字段、别名、转换和类型断言是否有消费者或必要边界。外部输入保留验证，内部已知类型避免反复防御；收窄已有类型优先于强转。
- **发布**：包导出、装配、运行时依赖、生成来源和实际打包内容是否一致；检查发布前置条件、取消与失败路径、说明文件生命周期和已发布兼容事实的保护。
- **验证**：缺陷要有可重现触发条件，回归测试应验证可观察行为。模型偶发与代码缺陷分别判断；真实运行、模型选择和证据边界遵守 playground 规则，不把历史快照冒充当前版本的验证。

## 修复与交付

每项发现写明位置、触发条件或维护成本、证据、影响与建议，区分已确认、待决策和未核实；按影响排序。遵守既有授权：只读请求止于报告，获准修复时修复已确认项；语义冲突、契约取舍或证据不足的项单列，继续其他工作。既有 accepted 决策中的有意取舍不重复作为缺陷。

运行项目要求的检查和与修改相关的验证，检查最终 diff 与生成物。没有新改动或失败时，不重复全套检查。报告实际覆盖范围、发现及处置、未核实项、命令结果和具体阻塞；测试通过不等于真实会话或发布已验证。

用户要求 PR 时，按根 `AGENTS.md` 的逐文件规则提交和建 PR，并在创建后对照远端文件列表核对正文。新增技能、文档调整与代码修复都需要原因。完成条件是授权范围已处理、验证有实际结果、PR 与逐文件说明一致；仅审查不执行版本发布。
