# upstream：按影响面同步

跟进 pstack 行为或当前功能依赖的 DSH 公共接口变化。

## 1. 确定影响面

记录更新前后版本，比较当前功能实际使用的上游行为与 DSH 公共接口，列出受影响的原子能力、`EXT-*`、移植交互点和已有 Issue。

- **pstack 更新**：检查受影响的原子能力、覆盖层、运行时脚本和 `dsh.md`。
- **DSH 更新**：检查受影响交互点的公共导出、SDK、插件声明与 UI 接口，运行兼容性测试，记录最低及最高已验证版本。
- **宿主已覆盖**：优先以公共能力替换本仓兼容逻辑，保留行为验收。

需要完整基线重建时，报告原因并交回 `/pstack-port audit`，保留 `docs/extensions.md` 的全部条目。

完成标准：每个使用已变更行为或接口的能力、扩展与交互点均有影响结论和更新后的证据；未受影响项保持原状。

## 2. 同步并验收

按影响清单修改手写实现、必要依赖、审查证据和扩展条目的兼容版本；每项修改建立或更新行为验证。

完成标准：每个受影响能力或扩展均有通过的验证；扩展条目的兼容版本与实际测试一致；仍受阻断的项目保留证据与具体原因。
