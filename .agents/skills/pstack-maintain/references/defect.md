# defect：复现、归因、报告、修复

处理安装后真实调用、路径、脚本、映射或界面行为的缺陷。

## 1. 真实复现与归因

在真实安装的 DSH 环境复现，记录最小步骤、输入、预期、实际结果、退出码和错误。测试与构建成功不能替代实际工具调用或界面验收。

以对照证据归因：

- **上游 pstack**：未移植的原行为已有同样问题，记录上游复现与版本。
- **本仓移植**：上游原行为正确，映射、覆盖层、Node 重写或插件集成后偏离。
- **DSH**：最小公共接口调用即可独立复现。
- **待确认**：证据只能缩小范围时，保留未决并写明下一次区分实验。

完成标准：缺陷有可重复步骤、准确版本、可观察影响和责任层证据；无法复现时保留未决及所需材料。

## 2. 记录并修复

Issue/待提交草稿至少记录：标题、维护分支、版本、环境、最小复现、预期/实际、责任层及证据、影响范围、回归测试、关联上游链接。按责任层提交到本仓、上游 pstack 或 DSH；本仓缺陷以本仓 Issue 为主记录，通过链接关联外部 Issue。

本仓缺陷修复后添加能区分修复前后的回归测试。其他项目的缺陷可先做有证据的兼容处理，标明外部 Issue、支持版本和移除条件；兼容状态按证据表述。

完成标准：Issue/待提交草稿与实际证据一致；本仓缺陷有通过的回归验证，外部缺陷有公开链接或经确认的待提交草稿；报告内容已脱敏。
