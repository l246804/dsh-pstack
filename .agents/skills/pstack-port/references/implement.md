# implement：实现 README 规定的插件能力

交付 README 插件内实现范围内的代码及必要的生产依赖。先冻结需求与 DSH API 方案，再读取现有实现；从 `docs/architecture.md` 确定当前手写实现位置，生成树与上游子模块只按架构规则维护。`docs/extensions.md` 中 `proposed` 与 `active` 条目是独立保留范围，其增量开发交给 `/pstack-maintain`。

## 1. 冻结本轮需求基线

确认 `<pstack>`、`<dsh>` 和 `pstack/README.md` 存在并记录上游提交。完整读取 README，提取原子能力编号、分类、插件内实现范围、缺口场景和验收行为；读取 `docs/extensions.md`，登记独立保留范围。

README 提交与当前上游不一致，或缺少能力编号、分类、实现范围、所需证据时，停止实现并报告需要重新运行 `/pstack-port audit` 的具体原因。逐项检查实现建议状态：每项必须是“已选择”或“证据唯一”。存在“待选择”时停止，展示该项候选、限制与取舍，请用户明确选择；确认后把“已选择”、所选方案、关键边界和确认日期写回 README，再继续。

读取现有实现前，用 `<pstack>` 文档和 `<dsh>` 源码复核宿主接口及待实现范围，冻结需求基线。

完成标准：每个待实现项都有上游行为、DSH 缺口、目标接口和可观察验收结果；README 与两个上游提交一致；每项实现建议均有“已选择”或“证据唯一”记录；范围尚未受旧实现影响。

## 2. 核对公共接口与依赖

对每个宿主交互点，沿 `<dsh>` 的正式导出、类型声明、SDK、插件包和调用示例确认插件可用的公共接口；读取实际包的 `package.json`、导出类型与实现，区分宿主内部能力和公共 SDK。

按优先级选择实现：

1. 复用可由依赖包导入的 DSH SDK、类型、schema、协议辅助函数和工具实现。
2. 使用有源码证据的公共插件接口。
3. 前两者不覆盖缺口时，在架构规定的手写位置实现插件专属逻辑，以最小接口隔离。

包导入使用 `<dsh>` 依赖声明和导出所证明的准确包名及兼容版本。运行时包加入根 `package.json` 的 `dependencies`，遵循工作区 catalog/版本协议，更新锁文件并确认实际安装；依赖来源使用包声明，而非 `<dsh>` 相对路径。公共导出与内部能力不同时，以公共导出为准，记录无法复用的具体原因。

完成标准：每个宿主交互都有 DSH 源码位置和导入来源；每项运行时依赖都有根生产依赖条目；手写声明均无法由已确认 SDK 替代。

## 3. 对照现有实现

需求基线和 API 方案冻结后，读取架构指出的覆盖层、运行时等手写实现，逐文件判定：

- **保留**：行为符合基线且未重复 DSH 能力。
- **修改**：接口或行为与当前证据存在明确偏差。
- **新增**：基线要求但尚不存在。
- **删除**：重复 DSH 能力、处理上游已移除行为、依赖不存在的宿主接口或仅服务旧抽象。

冻结基线优先于旧代码、注释和测试。需要重建时，先列出拟删除文件和符号，解析绝对路径并确认均位于架构规定的手写实现范围内，再清理并按已确认的 DSH 能力重建。保留 `proposed` 与 `active` 扩展条目，以及每个 `active` 扩展的实现和回归验证；其功能变更通过 `/pstack-maintain` 处理。

完成标准：每个待实现项映射到具体保留、修改或新增动作；每个重复或过时行为有处理结论；每个保留范围均可追踪；需求集合与冻结基线一致。

## 4. 实现并建立行为验证

本轮代码改动只实现 README 的插件内实现集合，并保留登记的本地扩展。DSH 标准模式或可选插件负责其已覆盖工作，本插件只实现证据规定的映射、编排和剩余缺口；平台排除项及其局部步骤保持排除。

遵循 `docs/architecture.md`、`docs/glossary.md` 和相关决策约定；架构边界、入口或术语变化时同步更新。实现公共接口、输入校验、生命周期、清理、错误传播和用户可见行为，使其符合上游场景与 DSH 语义；类型以声明包为准。

为每个 README 缺口建立可执行验证，覆盖具体场景、边界和失败路径；测试公共行为，而非复制实现的内部假设。修改范围限于当前需求所需的手写实现、生产依赖和文档，`dsh.md` 留给文档分支。

完成标准：每个实现项均有对应代码和至少一个行为验证；每个 `active` 本地扩展及其回归验证保持有效；所有宿主交互使用已核实的公共导入或接口；DSH 已覆盖能力没有替代实现。

## 5. 验证、报告并停止

从 `docs/`、环境已知命令或 package scripts 选择验证方式，执行最窄的相关测试、类型检查和构建，再执行受影响工作区的验证。逐项检查退出码；失败时区分本次实现、环境或既有问题并给出证据，本次未解决失败不得报告完成。

核对根生产依赖、锁文件、实际解析位置与源码导入一致。建立最终追踪表：

```text
README 能力编号 → 实现文件/公共接口 → 验证场景与结果 → 未解决限制
```

报告保留、修改、新增和删除的实现，新增生产依赖及其 DSH 来源，以及全部验证结果。逐项确认无需实现的映射、标准模式和可选插件能力未被重写；仍无法由公共 DSH 能力实现的项目保留证据与具体阻断。报告后结束本分支，等待用户显式调用 `doc`。
