# prepare：整理移植树与构建链路

在初次移植、上游更新或上一轮收尾后、`audit` 前整理 `pstack/` 的结构与移植机制。只处理目录、源码位置、本地适配树、生成与替换链路；需求调查、功能实现、行为审查和适配文档内容留给后续分支。

`prepare` 只结束本次调用，不结束本轮移植：报告后停止并等待 `audit`；本轮移植必须继续 `audit → implement ⇄ review → doc`，不能把结构整理当作交付。

开始前读取 `docs/port-review.md`。若存在活跃轮次（`轮次：#编号` 且 `收尾状态：未开始` 或 `docs/issues/<编号>/review.md` 仍存在，或 `轮次：baseline` 且 `审查状态` 为 `待审查`/`阻断-可修复`/`通过`/`阻断-待决策` 且 `收尾状态：未开始`），停止并报告当前轮次；由用户先完成该轮，或明确放弃后由 `audit` 重置，再执行结构整理。不要在活跃轮次中改变本地适配树或生成链。

## 1. 建立结构追踪

读取适用的已接受决策、`<pstack>/docs/harness/` 和上游生成脚本，枚举上游目录、本地适配树、runtime 与生成脚本，建立“上游路径 → 手写位置 → 生成位置 → 随包位置”的核对表。`<dsh>` 只用于核对当前插件组合与运行时约束，不作为上游结构来源。

遵循上游 CC 适配方式：上游文档、技能、playbook 和 reference 保持原文，DSH 文本差异只进入 `pstack/harness/`。当前实现只用于定位结构偏差，不用来反推新适配。

完成标准：每类上游资产都有唯一结构去向；每项偏差都定位到具体路径；上游子模块与生成树没有被当作手写源。

## 2. 整理本地适配树

枚举上游 `docs/harness/` 的适配文档，按契约核对本地文件：主适配器 `claude-code.md` 对应 `pstack/harness/docs/harness/dsh.md`，其他附件保持上游相对路径与文件名。新增附件按同一规则映射，不创建固定附件清单或无对应来源的文件。

移除过期适配文件、重复主适配器和无归属文本；只修改本地适配树及恢复生成机制所需的脚本，不重写上游正文。适配文档内容留给 `doc`。

完成标准：每个上游 harness 文件恰有一个本地产物；本地每个适配文件都有上游来源或明确的新增依据；没有重复主适配器或分散的上游文本适配。

## 3. 整理 runtime 镜像

按上游真实脚本路径核对：

```text
<pstack>/skills/<技能>/scripts/**
→ pstack/runtime/skills/<技能>/scripts/**
→ pstack/dist/runtime/skills/<技能>/scripts/**
→ dist/pstack/skills/<技能>/scripts/**
```

逐脚本标为 Node 等价实现、明确不移植或尚未移植，保留入口、参数、输出和测试的对应关系。清理无归属的重复入口、散乱目录和仅用于类型检查的设施；runtime 的行为修改与等价审查留给 `implement` 和 `review`。

完成标准：每个脚本都有镜像路径和明确去向；同一入口没有多套散置实现；构建后的路径能由替换规则消费。

## 4. 验证生成与替换链路

沿当前 package scripts 和构建配置验证：

1. `generate` 从上游原文与本地适配树渲染 `pstack/pstack/`；主适配器替换上游 CC 适配器，附件按映射进入。
2. 生成器按当前主适配器向需要映射的技能插入一次会话读取提示，检查名称映射、frontmatter 和相对链接；其他 harness 附件不被自动当作全局适配器。
3. `copy:pstack` 把生成树组装到 `pstack/dist/pstack/`。
4. runtime 编译保持镜像目录，`replace:scripts` 整目录替换随包脚本，只发布生产文件。
5. 根构建把 `pstack/dist/pstack/` 复制到发布树。

只修改 `pstack/` 内的文件、根或 `pstack/` 的构建与生成脚本，以及 `docs/port-prepare.md`；根插件实现与测试不属于本阶段。根插件集成或依赖需要修改时，记录为后续 `implement` 事项。架构含义变化时按仓库约定同步根 `docs/`。

可以运行生成器或 `generate --check` 做诊断，但它在适配文档更新前不是通过门禁。逐项区分结构已修复的问题、等待后续适配的问题和真正的生成缺陷；完整构建与真实行为验收留给后续阶段。

完成标准：结构、生成、复制、替换与发布路径逐段可追踪；本阶段范围内的结构检查通过；阻塞后续生成的问题都有明确归属；生成树只由生成器改变；根插件实现未被修改。

## 5. 报告并等待 audit

将本轮结构核对写入 `docs/port-prepare.md`，记录上游提交、目录映射、最小修正、诊断结果、仍需 `implement` 的问题和未决项。保留 README 与各审查工作文件，由下一次 `audit` 重置移植审查工作区。

报告后停止本次调用，等待用户显式调用 `/pstack-port audit`。普通 runtime 行为缺陷和局部实现修复不需要先运行本分支。

完成标准：`docs/port-prepare.md` 已记录基线、映射、修正、诊断和后续事项；README 与工作文件保持原状，未把结构整理当作本轮完成。
