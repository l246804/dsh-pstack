# prepare：整理移植树与构建链路

在初次移植、上游更新或审查发现结构漂移后、`audit` 前整理 pstack 的结构与移植机制。只处理目录、源码位置、本地 harness 适配树、生成与替换链路；需求调查、功能实现、行为审查和适配文档内容留给后续分支。

## 1. 建立结构追踪

读取适用的已接受决策、`<pstack>/docs/harness/` 及上游生成脚本，枚举上游目录、本地 harness 适配树、runtime 和生成脚本，建立“上游路径 → 手写位置 → 生成位置 → 随包位置”的核对表。`<dsh>` 只用于核对当前 DSH 插件组合与运行时约束，不作为上游结构来源。

遵循上游 CC 适配方式：上游文档、技能、playbook 和 reference 保持原文，DSH 文本差异只进入 `pstack/harness/`。当前实现只用于定位结构偏差，不用于反推新适配。

完成标准：每类上游资产都有唯一结构去向；每项偏差均定位到具体路径；上游子模块与生成树未被用作手写源。

## 2. 整理本地 harness 适配树

枚举上游 `docs/harness/` 的适配文档，按契约核对本地对应文件：主适配器 `claude-code.md` 对应 `pstack/harness/docs/harness/dsh.md`，其他附件保持上游相对路径与文件名。新增附件按同一规则映射，不创建固定附件清单或无对应来源的文件。

当前仓库仍是 overlay 旧结构时，把迁移到本地 harness 适配树及生成机制作为本分支的必要范围，同时更新架构与相关决策；不把旧目录当作继续使用的写入位置。移除遗留 overlay、过期适配文件、重复主适配器和无归属文本；只修改本地适配树及恢复生成机制所需的脚本，不重写上游正文。适配文档内容留给 `doc`。

完成标准：每个上游 harness 文件恰有一个本地产物；本地每个适配文件均有上游来源或明确新增依据；没有遗留 overlay 或重复主适配器。

## 3. 整理 runtime 镜像

按上游真实脚本路径核对：

```text
<pstack>/skills/<技能>/scripts/**
→ pstack/runtime/skills/<技能>/scripts/**
→ pstack/dist/runtime/skills/<技能>/scripts/**
→ dist/pstack/skills/<技能>/scripts/**
```

逐脚本标为 Node 等价实现、明确不移植或尚未移植，保留入口、参数、输出和测试的对应关系。清理无归属的重复入口、散乱目录和仅用于类型检查的设施；runtime 的行为修改与等价审查留给 `implement` 和 `review`。

完成标准：每个脚本都有镜像路径和明确去向；同一入口没有多套散置实现；构建后的路径能由替换规则消费。

## 4. 验证生成与替换链路

沿当前 package scripts 和构建配置验证：

1. `generate` 从上游原文与本地 harness 适配树重建 `pstack/pstack/`；主适配器替换上游 CC 适配器，附件按映射进入，`--check` 能发现漂移。
2. 生成器按当前主适配器向需要映射的技能插入一次会话读取提示，检查名称映射、frontmatter 和相对链接；其他 harness 附件不被自动当作全局适配器。
3. `copy:pstack` 把生成树组装到 `pstack/dist/pstack/`。
4. runtime 编译保持镜像目录，`replace:scripts` 整目录替换随包脚本，只发布生产文件。
5. 根构建把 `pstack/dist/pstack/` 复制到发布树，包清单、锁文件和依赖解析一致。

只修改恢复上述链路必需的生成脚本、构建配置和结构文件。检查无扩展名入口、替换列表和测试辅助文件是否被正确处理。行为语义需要改变时记录问题并交回 `implement`。

完成标准：结构、生成、复制、替换与发布路径逐段可追踪；相关构建与结构检查通过；生成树只由生成器改变；`docs/architecture.md` 与适用的决策反映迁移后的实际结构。

## 5. 报告并停止

将本轮结构核对写入 `docs/port-prepare.md`，记录上游提交、目录映射、最小修正、构建验证、仍需 `implement` 的行为问题和未决项。保留 README 与 `docs/port-review.md`，由下一次 `audit` 开始新调查并清空审查记录。

报告后停止，等待用户显式调用 `/pstack-port audit`。普通 runtime 行为缺陷和局部实现修复不需要先运行本分支。
