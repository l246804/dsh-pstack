# upstream：更新上游并评估影响

用于更新 pstack、DSH 或两者。产物是更新后的检出与影响评估；不运行构建，不启动后续分支，也不开始 port 轮次。

入口先检查 `docs/port-state.yaml`。blocker 非空或 `port.state: active` 时拒绝更新，报告当前工作项和可执行路由。只有 `idle` 才能继续。

## 1. 确认并更新

让用户选择上游并确认目标提交或版本。未指定目标时，先展示远端默认分支最新提交，再请求确认。检查上游工作区与本仓状态；有未提交改动、目标不明或会覆盖用户工作时停止。

在对应上游 fetch 并检出已确认目标，逐项检查退出码。更新后记录实际 HEAD 与本仓 submodule 状态，不代为提交，不直接编辑上游内容。全部已处于目标时报告“无实质更新”。

完成标准：范围、新旧提交和实际 HEAD 可回查；用户工作未被覆盖。

## 2. 只读影响评估

比较新旧提交与行为差异，读取 `docs/port-prepare.md`、`pstack/README.md`、`pstack/harness/`、runtime、插件实现和构建配置。`docs/port-review.md` 不作为分流依据。

按优先级给出唯一建议：

1. 目录、适配树、runtime 镜像或生成替换机制变化：`/pstack-port prepare`。
2. 上游需求、脚本行为、DSH 公共能力、插件组合或权限事实变化：`/pstack-port audit`。
3. 只需重新生成或复制产物：给出根构建命令，由用户执行，本轮结束。
4. 无实质影响：本轮结束，无下一步。

完成标准：每项变化都有影响结论与证据；建议入口唯一；没有把构建当作需求审查。

## 3. 报告并停止

报告更新范围、新旧提交、变化、影响、建议与理由。需要后续分支时写完整的 `/pstack-port prepare` 或 `/pstack-port audit`；只构建时给构建命令并写“本轮结束，无下一步”；无影响也写“本轮结束，无下一步”。

完成标准（R-09）：报告最后包含与影响评估匹配的完整 `/pstack-port ...` 命令，或明确的结束语；没有执行后续分支。
