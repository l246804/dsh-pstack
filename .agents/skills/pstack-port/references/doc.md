# doc：生成 DSH 移植文档

唯一目标文件是英文的 `pstack/overlay/docs/harness/dsh.md`。`pstack/README.md` 提供审查证据，`claude-code.md` 提供结构模板，当前手写实现证明插件实际能力；三者职责不同。

## 1. 固定模板与事实来源

确认两个上游路径和提交，完整读取 `<pstack>/docs/harness/claude-code.md`，逐项登记：

- 标题、引导段和每个 `##` 章节的内容角色与原始顺序。
- 每张表的列数、列角色、逐行条目和行顺序。
- 每个普通段落、列表项、示例及注意事项的语义与相对位置。

完整读取 `pstack/README.md`，确认其上游提交与当前一致。从 `docs/architecture.md` 确定当前手写实现位置，读取其中插件实际提供的入口、工具 schema、服务、事件和配置，形成已实现能力清单；其他现有代码、旧文档、生成树和构建产物不参与取证。

完成标准：模板全部结构和行均有位置记录；README 分类与插件内实现要求已提取；每项待写入的插件能力均能在当前手写实现中找到实际声明和行为。

## 2. 建立逐段映射

以模板为骨架逐段建立映射表，不继承 README 的审查章节结构。每个模板元素恰有一个去向：保留结构并替换为 DSH 内容，或按模板规定处理语义不适用项。

- **标题和引导段**：替换宿主名称与本地路径语义，保留一次会话读取、名称映射、无映射字段处理和 schema 合法性等指示。
- **Tools**：保留表结构和工具分支，替换为 DSH 实际工具名与降级方式；无对应工具时明确缺失。
- **Subagent fields**：逐字段、逐取值映射，保留只读、环境、后台、恢复、附件等原有分支，以 README 分类和 DSH 证据说明转换、插件支持或缺失。
- **Models**：保留模型 slug、非宿主模型、继承、角色规则和角色值等条目，替换为当前 DSH 的模型选择、规则文件和默认值语义。
- **setup-pstack**：保留 Detect、Defaults、Write 的步骤和约束，替换为 DSH 实际可检测模型、映射默认值、目标路径与写入格式。
- **Paths**：逐行转换技能、插件、规则、本地源码和 transcript 路径；路径来自 README 证据或实际插件行为。
- **平台特性差异段**：保留解释、处理指示、表格结构和全部功能分支。平台排除项沿用上游跳过说明；其余分支按 DSH 限制、可选插件条件、插件内能力或外部命令替换。

README 决定是否需要插件提供，当前手写实现决定插件实际怎样提供。二者冲突时暂停写作，报告能力编号与冲突，先重新调查或实现。可选插件写明准确 ID、启用条件和实验性状态，与标准模式明确区分。

完成标准：模板每个段落、表行和注意事项都有目标内容或有证据的处理结论；章节、表格和提示均来自模板。

## 3. 写入 dsh.md

完成独立映射后，读取已存在的目标文件以满足原位修改要求；旧内容不参与取证。按模板顺序写入 `pstack/overlay/docs/harness/dsh.md`，只改变 DSH 化所需内容。全文使用英文；专有名词、工具与字段标识、代码、路径及原文引用保持准确形式。

使用 DSH 的实际名称、工具参数、插件 ID、配置路径和回退行为。每项能力陈述追溯至 README；插件内能力同时对应真实工具或接口。按契约保留必要的 DSH 源码行证据链接，不增加模板没有的证据章节或改变表格结构。

能力状态以源码证据为准：规划能力标为规划，外部命令标为外部命令，原文要求的跳过、停止、降级或说明按 DSH 实际行为表达。

完成标准：目标文件与模板的标题层级、章节数与顺序、段落角色、表格数量和逐行覆盖一致；全部 DSH 名称与行为经 README 和当前手写实现复核。

## 4. 验证、报告并停止

并排核对模板与目标文件，逐章检查行覆盖和相对位置；逐项核对 README 的映射、标准模式、可选插件与插件实现集合，确认使用文档中的行为均位于原模板对应位置。

打开引用的源码证据，核对路径、行号、实际导出和工具 schema，检查 Markdown 相对链接可解析。报告两个上游提交、目标路径、逐章映射结果、有意不适用项及证据、发现的 README/实现冲突。本次只生成目标文档，实现、README 和依赖保持原状。报告后结束本分支。
