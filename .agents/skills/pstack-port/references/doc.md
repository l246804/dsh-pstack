# doc：按上游模板最小改写 DSH 适配文档

产物是 `pstack/harness/` 中由上游 `docs/harness/` 映射得到的英文适配文档，并只更新 `pstack/README.md` 的文档状态区与最终覆盖状态。README 提供需求与分类，当前手写实现和 bundle patch 证明实际能力，上游各适配文档独占对应产物的结构、格式与段落职责。

## 1. 核对审查基线并枚举文档

读取 `docs/port-review.md`，核对本仓提交、受审文件及内容哈希；基线不符，实现与必要验收未完成，或存在 `open`/`reopened`/`fixed-pending-review` findings、安全/权限阻断、行为错误、必要验收缺口时，先交回对应阶段。

确认两个上游路径和提交，枚举 `<pstack>/docs/harness/` 的适配文档。按契约建立输入与产物映射：`claude-code.md` 映射为 `pstack/harness/docs/harness/dsh.md`，其他附件保持上游相对路径与文件名。新增附件进入同一流程，无需修改技能。

逐份完整读取上游文档并登记：

- 标题、引导段和每个 `##` 章节的内容角色与原始顺序。
- 每张表的列数、列角色、逐行条目和行顺序。
- 每个普通段落、列表项、示例及注意事项的语义与相对位置。

完整读取 README，确认其上游提交与当前一致。从 `docs/architecture.md` 确定当前手写实现位置，读取入口、工具 schema、服务、事件、配置和 bundle patch，形成已实现能力清单；其他现有代码、旧文档、生成树和构建产物不参与取证。

完成标准：审查基线有效；每个上游 harness 文件恰有一个本地产物；每份模板的结构和行均有位置记录；每项待写入的插件能力均能在当前手写实现或 patch 中找到实际声明和行为。

## 2. 逐文件建立最小映射

分别以每份上游文档为骨架建立映射，不继承 README 的审查章节结构，也不把主适配器的章节强加给附件。每个模板元素恰有一个去向：保留结构并替换为 DSH 内容，或按模板规定处理语义不适用项。

主适配器至少覆盖以下原有元素：

- **标题和引导段**：替换宿主名称与本地路径语义，保留一次会话读取、名称映射、无映射字段处理和 schema 合法性等指示。
- **Tools**：保留表结构和工具分支，替换为 DSH 实际工具名与降级方式；无对应工具时明确缺失。
- **Subagent fields**：逐字段、逐取值映射，保留只读、环境、后台、恢复、附件等原有分支，以 README 分类和 DSH 证据说明转换、插件支持或缺失。
- **Models**：保留模型 slug、非宿主模型、继承、角色规则和角色值等条目，替换为当前 DSH 的模型选择、规则文件和默认值语义。完整模型 ID 保留内部 `/`，按第一个 `/` 分隔 provider 的既定适配在对应元素内简洁说明。
- **setup-pstack**：保留 Detect、Defaults、Write 的步骤和约束，替换为 DSH 实际可检测模型、映射默认值、目标路径与写入格式。
- **Paths**：逐行转换技能、插件、规则、本地源码和 transcript 路径；路径来自 README 证据或实际插件行为。
- **平台特性差异段**：保留解释、处理指示、表格结构和全部功能分支。平台排除项沿用上游跳过说明；其余分支按当前安装后实际组合、插件内能力或外部命令替换。

README 决定需要什么能力，当前实现决定实际如何提供。二者冲突时暂停写作，报告能力编号与冲突，先重新调查或实现。实验性插件只在当前 bundle 实际组合、且对应模板元素需要该行为时写入其运行效果；安装机制、实验性状态、插件推荐和候选比较留在 README。

脚本 Node 运行时和调用映射写入模板中承载对应脚本或工作流的现有元素；安全使用约束只有在实现已强制执行权限边界、且用户必须据此正确调用时才补充。文档不能声明“已审批”或“已沙箱化”来代替实际执行，也不能通过新增安全章节掩盖权限缺口。

完成标准：每份模板的每个段落、表行和注意事项都有目标内容或有证据的处理结论；每项新增或保留的表述都对应一个模板元素和一项真实行为；安装审查与候选方案没有混入使用文档。

## 3. 按最小差异写入适配树

完成独立映射后，读取已存在的本地产物以满足原位修改要求；旧内容不提供产品事实。按各模板顺序写入对应文件，全文使用英文；专有名词、工具与字段标识、代码、路径及原文引用保持准确形式。

优先保留与 DSH 无关且仍然成立的原文。只替换完成映射所需的名称、字段、路径、条件和行为；保留每份模板的章节数、顺序、段落数、表格数量、列角色、行数和提示方式。没有对应模板位置的内容不写入，不添加 Scripts、Host features、证据、安装、候选方案或审查章节。

链接仅保留模板原有链接的本地等价转换，以及缺失目标行为时不可缺少的使用链接；优先指向本地已安装文件或当前工具说明。审查证据与安装调查留在各自的阶段产物。

能力状态以源码证据为准：规划能力标为规划，外部命令标为外部命令，原文要求的跳过、停止、降级或说明按 DSH 实际行为表达。

完成标准：每个产物与对应模板逐元素对应；所有改动都有 DSH 化必要性；所有 DSH 名称与行为经 README 和当前实现复核；没有证据汇编、无来源附件或无关扩展内容。

## 4. 更新 README 覆盖状态

逐份并排核对模板与产物，检查结构、行覆盖、相对位置和最小差异。对每一处新增或删除说明它对应的 DSH 行为或模板排除规则；不能说明时恢复原样。逐项核对当前实现与必要验证，检查保留的相对链接可解析。

按能力 ID 更新 README 的文档状态区，记录产物路径、对应章节/表行、实际覆盖与有意不适用项；再更新最终覆盖状态：

- **完整实现**：当前实现满足该项上游验收行为，必要验证通过，无剩余行为缺口。
- **部分实现**：已实现的行为、具体未实现部分、原因、证据和关联 finding 均写清楚。
- **未实现**：缺少的行为、阻断或排除原因、证据和关联 finding 均写清楚。

只改文档与最终覆盖两块状态区，保留上游需求、DSH 分类、既定适配、实现记录和审查状态区的最近结论。详细审查工作记录在完成前留在 `docs/port-review.md`；完成后清理由该工作文件承担，README 继续保留当前权威状态。历史结论与当前源码不一致时，以当前证据更新状态并注明本次变化原因，不把矛盾结论堆入同一单元格。

完成标准：每个能力 ID 都有文档去向和最终覆盖结论；部分与未实现项的缺口、原因和证据完整；其他 README 区域未改变。

## 5. 清理审查工作文件、报告并停止

确认适配文档、README 更新和全部验证均已完成后，将 `docs/port-review.md` 重置为只含本轮标题、上游提交和“本轮已完成，无开放审查”的状态，删除本轮 findings、轮次、哈希和修复记录。文档或验证失败时保留报告；将受影响 finding 标为 `open` 或新建 finding，供 `implement` 修复。

报告两个上游提交、逐文件输入/产物映射、最小差异说明、最终完整/部分/未实现计数与逐项缺口、发现的 README/实现冲突，以及审查工作文件已清理。实现和依赖保持原状，报告后结束本分支。
