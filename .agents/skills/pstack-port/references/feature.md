# feature：登记并实现独立扩展

实现上游 pstack 未声明、需要随包交付的 DSH 版产品能力。功能只登记在 `docs/extensions.md`，与 `pstack/README.md` 的上游原子能力分开；具体需求来自用户本次请求与扩展条目，不在技能中预置功能或编号。

本分支独立于移植的 audit/review 状态机，不读取或修改 `docs/port-review.md`。读取 `docs/architecture.md` 和 `docs/extensions.md`，保留其他 `proposed` 与 `active` 扩展及回归验证。只实现本次明确请求的随包功能，不把仓库维护脚本当作已交付功能。

## 1. 登记范围与公共接口

为每项功能保留稳定的 `EXT-*` 编号，写清用户场景、范围、验收行为和状态。已有条目保持原编号，新条目使用下一个未占用编号。需要公开讨论或交付时关联本仓 Issue；公开提交 Issue、评论、日志或诊断附件前，展示目标仓库与脱敏后的完整内容并取得用户确认。

沿 DSH 的正式导出、类型、SDK、客户端插件入口、UI 插槽和文件服务确认公共接口及兼容版本，记录到扩展条目。发布源码使用的 DSH SDK、运行时服务包和类型包放入 `dependencies`，构建配置只承担编译与资源组装。优先复用宿主能力；本仓逻辑放在架构规定的手写实现位置，生成树和上游子模块按各自既有规则维护。每个新增文件、导出、工具、依赖和配置行都须对应当前验收行为或权限要求，避免重复 DSH 已有能力。

逐项列出模型触发的副作用及对应 DSH sandbox、审批和生命周期执行面；没有可保留必要边界的公共接口时，暂停该交付路径并报告阻断。

完成标准：扩展有稳定编号、明确验收行为、经源码确认的公共接口与兼容版本；每项副作用都有可验证的权限执行面。

## 2. 实现并验收

实现前为每个验收行为建立测试或真实交互检查。涉及用户文件时覆盖读取、合法写入、格式错误、保存失败、外部修改与刷新，并保护现有内容和授权边界。涉及界面时，在目标 DSH Web/Desktop 环境验证真实渲染和交互。按操作适用面验证权限拒绝、批准和取消。

执行最窄的相关测试、类型检查和构建，再执行受影响工作区及真实安装环境验收；runtime 不增加独立类型检查门禁。逐项检查退出码，本次未解决失败不得报告完成。

实现后更新扩展条目的实现位置、验证、兼容版本和状态。只有每个验收行为均有实现与通过验证时才标为 `active`；未完成的保持 `proposed` 并记录缺口。移除功能时先确认替代与迁移路径，再标为 `retired` 并记录原因，不能为绕过缺陷而静默退役。

完成标准：每个验收行为均有实现和验证；条目能追踪到代码、DSH 公共接口和兼容版本；权限边界经过验证；没有无归属文件或重复实现；扩展未混入上游原子能力集合。

## 3. 报告并停止

报告 `EXT-*` 编号、实现位置、公共接口、生产依赖、权限与真实安装验证、未解决限制及最终状态。公开提交遵循确认门；未完成或受阻时明确保留 `proposed` 与缺口。报告后结束本分支。
