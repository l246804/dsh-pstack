# refactor：技能重构收尾

只在用户要求重构 `pstack-port` 技能并完成 `SKILL.md`、`README.md` 或 `references/*.md` 修改后使用。这是维护任务，不是 `/pstack-port` 运行时分支，不读取或修改 port 轮次状态，也不执行 prepare、audit 或 doc。

## 1. 清理旧脚本（R-10）

先列出上一次重构新增或修改的相关脚本，再按当前技能引用、命令入口、生成链和测试逐项核对：

- 保留当前仍需要的脚本，验证行为与当前技能一致。
- 仍需保留的行为先迁移到当前手写源，再删除旧脚本。
- 删除不再需要的脚本及其专用测试、命令接线、生成配置、文档引用和空目录。
- 其他工作流仍引用的共享脚本保留，并更新调用方核验结果。
- 生成树与发布树只由生成器或构建刷新。

报告逐项列出保留、迁移和删除的脚本及理由。没有相关脚本时写「无旧脚本需要清理」。运行 `vp check`、`vp test` 与相关生成门禁，记录实际退出码。

完成标准：当前技能引用的脚本全部存在且有测试；旧脚本没有无引用的入口、测试、配置或文档残留；共享调用方未受影响；`vp check`、`vp test` 与相关生成门禁退出 0。

## 2. 整技能审查（S-29、R-13）

按 `/writing-for-agents` 通读 `SKILL.md`、`README.md` 与全部 `references/*.md`。检查信息层级、重复与散落、无效句、指针措辞、leading word 和术语一致；同时逐条核对 S-01～S-29 与 R-01～R-14 的分支覆盖，确认每条原要求仍可定位。涉及 SPEC 的语义冲突只按用户已确认的结论执行，并在报告中列出冲突项与结论；没有冲突写「无」。

发现的问题直接修复。审查不改技能的功能范围、分支或用户锁定的 `SPEC.md`，不为审查新增功能章节。

运行：

```bash
vp check
vp test
```

报告列出「整文档审查」的修改点，无修改写「无」。同时列出脚本处置、场景覆盖、验证命令与实际退出码。

完成标准（S-29、R-09、R-13、R-14）：所有技能文件已通读；每条原要求仍可定位，冲突项有用户结论；旧脚本处置有结论；29 个场景都有执行位置和可执行验收；`vp check` 与 `vp test` 退出 0；报告含整文档审查记录；本轮结束，无下一步。
