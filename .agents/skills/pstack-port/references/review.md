# review：审查实现、权限与最小性

在 `implement` 后、`doc` 前审查实现，只更新 `docs/port-review.md` 和 README 的审查状态区。输入是 README、两个上游、适用的已接受决策，以及当前手写实现、依赖、bundle patch、测试和真实安装验证结果；插件实现与测试保持原状，构建结果只作为一项证据。

## 1. 固定审查范围

确认 README 与两个上游提交一致，逐项取得原子能力、既定适配、实现选择、公共接口和验收行为。读取上一轮报告的文件哈希、finding 状态和 `fixed-pending-review` 修复记录，比较当前文件与受影响调用链。

首轮详审全部当前手写实现与发布配置；后续轮次详审修复文件、受影响调用方、权限边界、组合行和相关验收。已有结论仅在其证据、代码及依赖未变化时保留；受影响的关闭 finding 重新打开，新发现的问题分配新 ID。每轮都重新执行全量能力去向、权限和必要验收门禁，以增量审查形成整体结论。

读取 `<dsh>` 中对应公共 API、服务定义、提供者、消费者、bundle patch、权限执行面和测试。其他手写插件只能作为参考，不能替代公共接口证据。

完成标准：每个实现项、既定适配、发布依赖和模型触发副作用均有审查位置；缺失 README 基线或证据时停止并报告。

## 2. 审查 DSH 插件开发范式与能力复用

逐项检查：

- 使用公开导出、声明包和当前版本支持的插件接口；服务定义、提供者与消费者完整，类型和运行时导入可解析。
- bundle patch 按 DSH 行 ID 与组合语义声明依赖、启用、覆盖和互斥；宿主已提供的能力直接复用，缺失的必要行随本插件启用，没有重复注册或运行时擅自改写 profile。
- 声明式组合能够表达的行为没有另写服务、工具或配置系统；DSH SDK、类型和 schema 能替代的手写声明没有保留。
- 生产运行与类型依赖在 `dependencies`，构建配置没有用来隐藏错误依赖分层；锁文件与导入一致。
- 工具、生命周期、错误传播、取消、配置与资源路径符合宿主语义，没有把 Cursor 抽象原样套到 DSH。

发现未决设计选择时，回到对应候选与决策证据；已经形成长期取舍的改动按 `docs/decisions/AGENTS.md` 提出记录要求。

完成标准：每个宿主交互都有最贴近当前 DSH 公共能力的实现依据；每项自行实现的逻辑都有 DSH 无法直接覆盖的具体证据。

## 3. 审查权限与安全边界

列出每个模型可见工具和脚本入口的完整副作用，沿调用链检查到实际执行点：进程、文件、网络、安装、远程操作、后台任务和清理。确认副作用进入对应 DSH sandbox、审批与生命周期执行面，并核验拒绝后未执行、批准后仅执行所批准范围。

重点检查直接 `spawn`、shell、任意路径、环境继承、外部命令和插件进程内权限。按契约核验实际权限执行；边界未证实的项目记为高优先级阻断，退回 `implement`。

完成标准：每个副作用都有执行面与拒绝/批准验证；没有模型可控的未授权旁路；残余限制明确到接口或场景。

## 4. 审查最小性与残留

按“删除后是否影响 README 验收”审查每个新增文件、导出、工具、依赖、配置行、适配层、兼容分支、文档段和测试辅助设施。保留项必须对应当前能力、既定适配或安全要求。

检查重复 DSH 能力、未引用文件、空实现、旧路径、旧工具名、重复类型、被替代依赖、调试产物、临时脚本、测试残留、过期注释与生成/手写边界错位。生成树只由生成器维护；目录或构建链路漂移交回 `prepare`，runtime 行为偏差交回 `implement`，删除建议解析到具体路径与引用证据。

完成标准：每个保留项都有当前消费者或验收依据；每个冗余项都有可执行删除建议；没有无归属文件或过期实现残留。

## 5. 验证并更新审查台账

选择能反驳审查发现的现有测试或只读检查；实现与测试保持原状。需要新增回归验证才能证明问题时，把它列为 `implement` 的明确补修项。

按严重度报告：安全/权限阻断、行为或公共 API 错误、非最小实现、冗余残留、验证缺口。每项包含能力编号、文件/行、证据、影响和退回阶段；没有发现时逐项明确写“无”。

更新 `docs/port-review.md`：保留本轮此前各轮 findings、修复与关闭记录，追加本轮编号、本仓提交、受审文件清单及内容哈希；`fixed-pending-review` 验证通过改为 `closed`，未通过改为 `reopened`，新发现从 `open` 开始。只更新 README 中本次涉及能力的审查状态区，记录最近审查轮次、结论和开放 finding ID，保留其他阶段记录。

完成本轮全部实现与必要验收，且不存在 `open`/`reopened`/`fixed-pending-review` findings、安全/权限阻断、行为错误和必要验收缺口时，才建议进入 `doc`。存在开放 findings 时退回 `/pstack-port implement` 增量修复；仅有已关闭 findings 但实现未完成时，也继续 `implement`。非阻断的最小性与冗余问题单独列出，由用户决定本轮清理或后续维护。

本轮报告在中间修复和审查通过后保留，供 `doc` 核对；`doc` 成功后清理，未完成时由下一次 `audit` 重置。报告后结束本分支。
